# Formulon 0.19.0

0.19.0 settles the public API into one naming convention across C, JavaScript and Python, and brings calculation, file conversion and workbook editing closer to Excel 365. It contains breaking changes in every binding: read [Upgrading from 0.18 to 0.19](https://github.com/libraz/formulon/blob/v0.19.0/docs/releases/upgrading-0.19.md) before updating. The full list of changes is in the [CHANGELOG](https://github.com/libraz/formulon/blob/v0.19.0/CHANGELOG.md#0190---2026-11-23).

## Highlights

- One API shape in every binding: sheet-scoped calls live on a `Sheet` handle, tables, PivotTables and drawings are handle classes, and failures are thrown as `FormulonError` rather than returned as status envelopes.
- Chartsheets load, save and convert between `.xlsx` and `.xlsb`.
- PivotTables refresh from their worksheet source, group numeric and date fields, and evaluate every filter type.
- Insert Cells and Delete Cells, worksheet copy, and table row, column and rename edits rewrite references the way Excel does.
- Pictures in cells are a value kind of their own and travel through formulas.

## Excel compatibility

The reference set the engine is checked against grew from 9,581 to 14,669 formulas and workbook cases, each compared with the value Excel 365 gives, across the same fourteen locales. Every case either matches or is listed as a documented difference.

Where 0.19.0 matches Excel and 0.18.0 did not:

- **Same bits on every host.** Trigonometric, exponential, logarithm and power functions, and everything built on them (distributions, regression, financial functions), give the same result on macOS, Linux and WebAssembly. Results can move in the last bit relative to 0.18.0.
- **References as results.** `OFFSET`, `INDIRECT`, `INDEX`, `XLOOKUP`, `TAKE`, `DROP`, `IF`, `CHOOSE` and `LET` return the reference they select, so `SUBTOTAL`, `COUNTIF`, `SUMIF` and the `*IFS` family read it like a range written directly. 3-D references follow Excel's rules under `:`, intersection, union and as an arm of `IF`, `CHOOSE`, `IFS` and `SWITCH`.
- **Lookups.** Blank lookup values, wildcard folding, array indexes in `VLOOKUP`, `HLOOKUP`, `CHOOSE` and `INDEX`, and approximate search over a whole row or column.
- **Conditional aggregates and database functions.** Criteria that name an error, the shape of the `SUMIF` and `AVERAGEIF` value range, and errors in matched `D*` fields.
- **Financial and statistical functions.** `AMORDEGRC`, coupon schedules, `IRR`, `MIRR`, `XIRR`, `XNPV`, `YEARFRAC`; `PERCENTILE`, `QUARTILE`, `PERCENTRANK`, `FREQUENCY`, `LINEST`, `LOGEST`, `TREND`, `GROWTH`.
- **Which error a call reports.** When several arguments fail, the error returned is the one Excel returns.
- **Dynamic arrays.** More functions evaluate per element over array arguments, and `#`, `@` and one-cell ranges read as Excel reads them.
- **Formula entry.** Formulas Excel refuses to enter are refused: fixed argument counts, a `:` endpoint that cannot be a reference, a typed `ANCHORARRAY` call, an external sheet name over 31 characters, a chartsheet as a reference target. These are breaking for callers that entered such formulas.
- **Tables and names.** Structured references read as the range they cover in every function, and table and defined names Excel refuses are refused.
- **Other workbooks.** External links whose refresh failed read `#REF!`, and a save writes only the links something references, numbered as Excel numbers them.
- **PivotTables.** Row and column grand-total flags are no longer swapped when read from or saved to `.xlsx`; a report that cannot be drawn is blocked with `#SPILL!` on its anchor.
- **Conditional formatting and validation.** Text rules follow their stored formula, rules that reference another sheet round-trip in both formats, and ranges split, join and extend around inserted and deleted cells as Excel does.
- **File conversion.** Cell watches, ignored errors, scenarios, headers, footers and page breaks survive conversion between `.xlsx` and `.xlsb`; built-in number formats and theme fonts are saved as Excel saves them.
- **Text positions.** `LEN`, `MID`, `FIND`, `SEARCH` and `REPLACE` count by the workbook's Compatibility Version.

## Still different from Excel

- `IMAGE`, `STOCKHISTORY`, `WEBSERVICE`, `TRANSLATE`, `DETECTLANGUAGE`, `PY` and `COPILOT` do no network I/O and return a fixed error.
- A circular reference with iterative calculation off is `#REF!` for every cell in the cycle; Excel's values depend on the order of entry, which a file does not record.
- Generated arrays are capped at 1,048,576 cells, below Excel's limit.
- Formulas on macro sheets are not loaded.
- Page-break positions are exact for the calibrated fonts and approximate for others.

Every known difference is listed case by case, with its reason, in [`tests/divergence.yaml`](https://github.com/libraz/formulon/blob/v0.19.0/tests/divergence.yaml).

## Breaking changes

All of them, with before-and-after code, are in the [upgrade guide](https://github.com/libraz/formulon/blob/v0.19.0/docs/releases/upgrading-0.19.md). In brief:

- Names follow one convention in C, JavaScript and Python; the former names are removed without aliases.
- Sheet-scoped calls move to `wb.sheet(key)`; tables, PivotTables, pivot caches and drawings are handles.
- Failures throw or raise `FormulonError`.
- Formula entry and several setters refuse input Excel refuses.
- An `.xlsb` save fails with `IoFeatureNotWritable` instead of dropping a feature it cannot write.
- `fm_workbook_load` takes an options argument, and several status codes are retired.
- A cell holding an in-cell picture reads as the value kind `Picture` where it read `#VALUE!`.
- A loaded workbook keeps its cached values when Excel would; `recalcFull()` recomputes everything.

## Install

```sh
npm install @libraz/formulon@0.19.0
pip install formulon==0.19.0
```

Command-line binaries for macOS (arm64) and Linux (x64, arm64) are attached to this release.
